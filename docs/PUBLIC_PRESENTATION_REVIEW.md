# Public presentation and research-integrity checklist

Review date: 2026-11-10. This is a documentation checklist, not an independent reproduction or an endorsement of scientific claims.

## Keep the public identity consistent

- Project name: ScientificDiscoveryLab.
- Public tagline: Beyond the Known.
- Scope: independent computational research, experimental software, and transparent reporting of limitations.
- Link the research repository, experiment registry, current status, and audit documents from any public showcase.
- Keep branding and promotional artwork distinct from measured results. Label illustrative diagrams and concept graphics.

## Evidence before claims

- Preserve the repository's explicit statement that no physics discovery is claimed.
- Distinguish preregistered questions, synthetic controls, measured observations, preliminary analyses, and verified findings.
- Retain negative findings, known defects, withdrawn certifications, and instrument limitations in summaries.
- Check every experiment count and test count against the current registry and a fresh test run before using them in graphics or social media.
- Review the DOI badge at the top of the README alongside the DOI links in the project status table. Confirm their respective records and versions before presenting one as the canonical publication.
- Never edit raw research data or append-only registries merely to make documentation look consistent.

## Quality gate for future changes

1. Record current branch, commit and clean environment.
2. Run relevant existing tests and preserve the outputs.
3. Inspect documentation links, image alt text, screenshots and attribution.
4. Check dependency updates against lockfiles and supported Python versions.
5. Review security and licensing before publication.
6. Submit changes through reviewable pull requests and report unverified checks explicitly.

## Public-facing design suggestions

Use a consistent visual system across the GitHub README and social graphics, but do not imply that a rendered scientific illustration is a real experimental output. When presenting a plot, include source experiment, run identifier, units, controls and a limitations note.
